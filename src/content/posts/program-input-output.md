## 文件描述符

File descriptor（fd）是文件描述符。进程有一张文件描述符表，每个描述符对应一个打开的内核对象。

```text
进程
└── 文件描述符表
     0 → 某个内核对象
     1 → 某个内核对象
     2 → 某个内核对象
     3 → 某个内核对象
     ...
```

在 C 里，可以使用 `open()` 打开文件来获得文件描述符，例如 `int fd = open("test.txt", O_RDONLY)`。

Unix 和 Linux 程序通常约定以下三个描述符。

```text
0 → 标准输入
1 → 标准输出
2 → 标准错误输出
```

## 进程如何得到文件描述符

父进程创建子进程时，子进程会继承打开的文件描述符。比如 Shell 可以调用 `fork()` 创建子进程，子进程再用 `execve()` 加载程序。执行新程序时，标记了关闭执行（`close-on-exec`）的描述符会关闭，其余仍可使用。

系统启动后，通常由 PID 1（如 systemd）负责启动其他服务。我们使用 `systemctl` 管理服务，便是通过它与 systemd 通信，后者根据 unit 文件启动程序。

交互式终端下，进程的标准输入、标准输出和标准错误通常都连到同一个终端。使用重定向或管道时，它们可以各自指向不同的对象。

## 进程输入输出的实现

以标准输出连到终端为例。

```text
stdout
 ↓
fd 1
 ↓
内核
 ↓
终端
```

可以用 `dup2()` 将标准输出指向打开的文件。管道也是通过让一端进程的输出和另一端进程的输入连接到对应的描述符来实现的。

如果标准输入连到终端，一次读取大体会经过这些步骤。

```text
read(0, buf, 100)
      ↓
libc 封装与系统调用
      ↓
内核查进程的描述符表
      ↓
找到 fd 0 对应的 struct file
      ↓
调用对象的读取操作
      ↓
从终端获取输入并复制到用户空间 buf
      ↓
返回读取字节数
```

## mmap()

`mmap()` 在进程的虚拟地址空间里创建一段映射，这段映射可以对应文件，也可以是匿名内存。匿名映射没有对应的文件。比如申请一块私有的可读写匿名内存，可以把地址设为 `NULL`，由内核选择地址，同时使用 `PROT_READ | PROT_WRITE` 和 `MAP_PRIVATE | MAP_ANONYMOUS`。

可执行文件的加载同样涉及将文件内容映射到内存，加载器需要的信息记录在 [ELF文件结构](../elf-file-structure/) 里介绍的程序头表中。
